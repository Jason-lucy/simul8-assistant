# Simul8 排队、资源与瓶颈分析

## 排队系统核心指标

- **到达率 λ**：单位时间到达数量
- **服务率 μ**：单位时间可服务数量
- **利用率 ρ**：资源忙碌比例
- **平均等待时间 Wq**、**平均队长 Lq**
- **吞吐 Throughput**：系统稳定产出

当某个 Activity 长期高利用率且其前方 Queue 持续增长，通常就是瓶颈。

## 在 Simul8 中识别瓶颈

1. 查看各 Activity 的 Resource Utilization。
2. 查看各 Queue 的 Average Queue Size / Maximum Queue Size。
3. 结合等待时间分布，判断是偶发峰值还是结构性不足。
4. 用试验：只给疑似瓶颈 +1 资源，观察吞吐是否显著上升。若几乎不变，瓶颈可能在别处。

## 资源建模建议

- 人与机器分开建模，避免“一个资源干所有事”掩盖约束。
- 班次、休息、故障要用日历或可用性设置，否则白天高峰结论偏乐观。
- 共享资源（如质检员服务多条线）要显式绑定，否则并行线会被高估。

## Routing 与优先级

- 简单分流可用概率 Routing。
- 按类型/紧急度分流，优先用 Label 携带属性，再按 Label 路由。
- 优先级队列：紧急单插队时，要评估对普通单等待时间的副作用。

## 市场与售前可用话术（基于仿真）

“我们不是拍脑袋加资源，而是用 Simul8 把到达、处理、班次和故障建成可试验模型。先定位瓶颈，再比较方案的吞吐与等待时间，给客户可量化的改进区间。”
